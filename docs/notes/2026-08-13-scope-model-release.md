# SCoPE model release audit

## Decision

Publish a complete inference model rather than the original distributed training checkpoint or a
partial parameter overlay. The Hugging Face repository is self-contained and does not require a
second Wan2.2-I2V-A14B download.

## Why the training checkpoint is not the release artifact

The selected 32K PyTorch DCP metadata contains 6,988 entries:

- 3,586 model entries: 1,575 high-noise DiT, 1,575 low-noise DiT, 242 T5, and 194 VAE;
- 3,402 optimizer entries, including first- and second-moment tensors.

The historical inference path assembled the official Wan2.2 pipeline, installed SCoPE in both
experts, then overlaid the trained high-noise state selected from the DCP. That procedure is the
source of truth for export, but a DCP training snapshot is not an appropriate public model file.

## Published model boundary

The clean model bundle contains:

- a complete 1,575-entry high-noise SCoPE DiT;
- a complete 1,575-entry low-noise DiT with the same official behavior used in local inference;
- the 242-entry T5 state dictionary;
- the 194-entry VAE state dictionary;
- the matching tokenizer; and
- `model_index.json`, component configs, and safetensors indexes.

The two DiTs are stored in sharded safetensors. T5 and VAE retain their upstream pure-tensor state
dictionary format. No DCP metadata/shards, optimizer, scheduler, trainer state, or delta loader is
part of the public model.

## Verification

The following checks passed:

1. Strict component loading found no missing, unexpected, duplicate, or unmaterialized keys.
2. Both DiTs contain 1,575 state entries and expose the same complete key set.
3. T5 and VAE load with `weights_only=True`; every top-level value is a tensor.
4. The complete bundle loads high/low DiTs, T5, VAE, and tokenizer without consulting a base-model
   directory or DCP checkpoint.
5. In the same locked evaluation environment, the complete-model CLI and the
   official-base-plus-32K-DCP path generated byte-identical Cambridge videos with SHA-256
   `2f46367972a6f11ce2f8c29a62aab3874315a519c380ffd7cf8d180e1c5e8c2a`.
6. The portable historical output has SHA-256 `b36aaf657bf71d4f51001a5b66af623003212b873b3d9daf8c643becc20d67e9`.
   The same inputs, seed 42, fallback attention backend, and weights produced a different hash on
   the current node, so historical hashes are treated as environment-specific references.

## OmniWorld example alignment audit

Three provisional `omni-city-*` labels came from release curation rather than OmniWorld metadata
and did not describe their images. They were replaced with content-based public IDs while keeping
the immutable source IDs and gallery entries unchanged:

| Public case | Source ID | Original caption file |
| --- | --- | --- |
| `omni-misty-forest` | `135f09dd0200_split0_000001` | `text/000001_000081.json` |
| `omni-rocky-forest` | `135f09dd0200_split3_000594` | `text/000594_000674.json` |
| `omni-stained-glass-hall` | `0b3caf48b79d_split3_000414` | `text/000414_000494.json` |

For all three cases, the released first-frame PNG is byte-identical to the indexed OmniWorld color
frame, the caption is exactly the source `Video_Caption`, and the published horizontal FOV equals
the value recomputed from source intrinsics. Every listed pose is also byte-identical to the
corresponding historical gallery evaluation pose.

## Public naming and documentation audit

The `omni-city-drive`, `omni-city-drive-alt`, and `omni-city-flight` strings do not occur in the
OmniWorld metadata or the historical gallery builder. The source gallery labels both relevant
scene hashes only as `Game World`. The first occurrence that can be recovered is the provisional
release manifest, so `city` was introduced during release curation rather than copied from a
prompt, source title, or dataset field.

All 21 public IDs were reviewed against their first frames and source captions. Two additional
curation errors were corrected:

- `omni-market` became `omni-urban-street`; its source caption describes an urban street and the
  first frame contains no market.
- `istock-motorbikes-sunset` became `istock-cyclists-sunset`; the source title's “sports bikes”
  was previously misread, while both the first frame and caption show road cyclists.

The remaining IDs are literal scene descriptions supported by their frames and captions. Source
IDs, gallery entries, prompts, poses, and hashes were not changed by the public-ID cleanup.

The README and model card were then rewritten around the public workflow: installation, model
download, Python inference, custom inputs, multi-trajectory inference, RDPO high-only training,
the unified RealEstate10K-style data protocol, citation, and acknowledgements. Internal export,
DCP, checkpoint-selection, regression-hash, evaluation, and integrity-check narratives were
removed from user-facing documentation.
